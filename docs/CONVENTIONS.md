# Engineering conventions (binding for both repos)

Source: the team's production reference guide. Every change must follow this.

## Backend layering (strict, no skipping)
`Router -> Handler -> Helper -> DB Service` (+ External Service called from helpers only)
- **routes/** `*-router.ts`: method + path + middleware wiring only.
- **handlers/** `handle*`: parse validated request, call a helper, respond.
- **helpers/** `*-helper.ts`: business logic, orchestrates DB + external calls; unit tests in `helpers/__tests__/`.
- **services/database/** `*-db-service.ts`: every Drizzle query lives here, no business logic.
- **services/** (github, slack, sheets): wrap external systems.
- **middlewares/** (`is-authenticated`, `is-authorized`, `rate-limiter`, guards), **validations/** (`validate-req.ts`, `schemas/<domain>/`, schema names prefixed `v`), **exceptions/** (always throw typed exceptions, never `new Error` for HTTP cases, never `c.json({error})` for failures), **utils/** (pino-logger, jwt/cookie/tz/resp utils), **constants/**, **types/**, **seeders/**, **migrations/** (Drizzle Kit output, never hand-edited, committed with the schema change).
- **Config:** `process.env` only in `env.ts`; `config/*.ts` one file per external service consumes it. Fail fast on missing vars.

## TypeScript
- tsconfig: `strict`, `noUncheckedIndexedAccess`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, `exactOptionalPropertyTypes` (plus unused-locals/params, verbatimModuleSyntax).
- No `any` (use `unknown` + narrowing). No `!` non-null assertions. No unnarrowed `as` casts.
- `type` for shapes/unions; `interface` only when extending. Discriminated unions instead of optional-flag state. `satisfies` to validate without widening. `as const` for literal tuples/maps. Specific generic constraints. Type predicates for narrowing. `Readonly` for data that must not mutate.
- No enums: const object + derived type.
- Explicit return types on all exported functions.
- Enforced by ESLint (`npm run lint`).

## Naming
Components PascalCase files; hooks `useX.ts`; services/routes/constants kebab-case files; schemas prefixed `v`; handlers `handleX`; helpers action verbs; constants SCREAMING_SNAKE; booleans `is/has/can`; event handlers `onX`.

## Frontend rules
- File-based TanStack Router: route files hold no logic, they render one page component. Default export for pages, named export for shared components. One component per file, props type `[Component]Props` above it.
- Folders: `routes/`, `components/<domain>/` (+`core/`, `ui/` shadcn untouched), `features/` for isolated slices, `hooks/` (cross-domain data hooks), `https/` (fetch.ts + services/ raw API calls, no business logic), `lib/` (queryClient, auth session, routePermissions, usePermission, constants/ per domain, interfaces/ per domain), `middleware/routeAuthMiddleware.ts`.
- One concern per hook. Server data stays in TanStack Query (never copied into useState). Gate lazy queries with `enabled` (dropdowns/popovers). Context only for real deep-tree sharing.
- States: `isLoading` -> spinner, `error` -> ErrorState, unloaded values -> `--` (not skeletons) per the reference guide.
- No magic strings in components (constants file per domain). Specific, actionable error messages. Comments explain only *why*.

## Commit/build discipline
- `tsc --noEmit`, lint and tests pass before every commit; `npm run build` must pass.
- One deployable unit per commit, no "WIP". Migrations generated by `npm run migrations:gen` and committed with the schema change.
- Reference guide says "commit dist/ with src/" for the backend; we build on Railway instead, so `dist/` is not committed unless the team asks.
